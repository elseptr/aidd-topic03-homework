# Новые возможности проекта Investing Demo

**Дата реализации:** 2026-10-30  
**Статус:** реализовано  
**Версия:** 1.0

---

## 1. Обзор

В проект добавлены 4 крупных функциональных блока:

1. **Watchlists и ценовые уведомления** — списки наблюдения за акциями с целевыми ценами и уведомлениями
2. **Виртуальный инвестиционный портфель** — моделирование покупки/продажи акций с расчетом прибыли/убытка
3. **Исторические цены и графики** — хранение и отображение истории котировок с поддержкой разных периодов
4. **Симулятор инвестиционных стратегий** — тестирование торговых стратегий на исторических данных

Все функции реализованы с учетом существующей архитектуры проекта (Django, классовые представления, сервисный слой, Celery задачи).

## 2. Watchlists и ценовые уведомления

### 2.1 Модели данных

| Модель | Описание | Ключевые поля |
|--------|----------|---------------|
| `Watchlist` | Список наблюдения пользователя | `user`, `name`, `created_at`, `updated_at` |
| `WatchlistItem` | Связь акции со списком наблюдения | `watchlist`, `share`, `added_at` |
| `PriceAlert` | Ценовое уведомление | `user`, `share`, `target_price`, `alert_type` (above/below), `is_active`, `last_triggered_at` |
| `Notification` | Уведомление пользователя | `user`, `message`, `is_read`, `created_at` |

### 2.2 Функциональность

- **Создание и редактирование списков наблюдения** — пользователь может создавать несколько списков с уникальными именами
- **Добавление и удаление активов** — в список можно добавить акцию по FIGI, удалить акцию из списка
- **Установка целевой цены** — пользователь устанавливает целевую цену и тип уведомления (цена выше / цена ниже)
- **Защита от дублирующихся уведомлений** — одно и то же уведомление не срабатывает чаще одного раза в час (проверка по `last_triggered_at`)
- **Просмотр уведомлений** — список всех уведомлений с возможностью пометить как прочитанные

### 2.3 Представления (Views)

| URL | Представление | Описание |
|-----|---------------|----------|
| `/watchlists/` | `WatchlistListView` | Список списков наблюдения |
| `/watchlists/create/` | `WatchlistCreateView` | Создание списка |
| `/watchlists/<pk>/` | `WatchlistDetailView` | Детали списка с акциями |
| `/watchlists/<pk>/delete/` | `WatchlistDeleteView` | Удаление списка |
| `/watchlists/<pk>/add-share/` | `WatchlistAddShareView` | Добавить акцию по FIGI |
| `/watchlists/<pk>/remove-share/<item_id>/` | `WatchlistRemoveShareView` | Удалить акцию из списка |
| `/alerts/` | `PriceAlertListView` | Список ценовых уведомлений |
| `/alerts/create/` | `PriceAlertCreateView` | Создание уведомления |
| `/alerts/<pk>/delete/` | `PriceAlertDeleteView` | Удаление уведомления |
| `/notifications/` | `NotificationListView` | Список уведомлений |
| `/notifications/<pk>/read/` | `NotificationMarkReadView` | Пометить прочитанным |
| `/notifications/read-all/` | `NotificationMarkAllReadView` | Пометить все прочитанными |

### 2.4 Сервисный слой

- `WatchlistService` — создание списков, добавление/удаление акций
- `PriceAlertService` — создание уведомлений, проверка срабатываний при обновлении цен
- `NotificationService` — подсчет непрочитанных, отметка как прочитанные

### 2.5 Ограничения

- Уведомления проверяются только при обновлении цен через Celery задачу `update_last_price`
- Если Tinkoff API недоступен, используются демонстрационные данные (см. раздел 6)
- Защита от дублирования: уведомление не повторяется чаще одного раза в час

## 3. Виртуальный инвестиционный портфель

### 3.1 Модели данных

| Модель | Описание | Ключевые поля |
|--------|----------|---------------|
| `Portfolio` | Виртуальный портфель | `user`, `name`, `initial_balance`, `created_at` |
| `PortfolioPosition` | Позиция (количество + средняя цена) | `portfolio`, `share`, `quantity`, `average_price` |
| `PortfolioTransaction` | Операция покупки/продажи | `portfolio`, `share`, `transaction_type`, `quantity`, `price`, `total_amount`, `executed_at` |

### 3.2 Функциональность

- **Создание портфеля** — с указанием названия и начального баланса
- **Покупка акций** — с указанием FIGI, количества и цены; проверка достаточности баланса
- **Продажа акций** — с проверкой наличия достаточного количества в портфеле
- **Расчет средней цены покупки** — взвешенное среднее при докупке
- **Расчет текущей стоимости** — на основе последней цены акции из `Share.last_price`
- **Расчет прибыли/убытка** — в абсолютных величинах и процентах
- **История операций** — все покупки и продажи с датами и суммами

### 3.3 Представления (Views)

| URL | Представление | Описание |
|-----|---------------|----------|
| `/portfolios/` | `PortfolioListView` | Список портфелей |
| `/portfolios/create/` | `PortfolioCreateView` | Создание портфеля |
| `/portfolios/<pk>/` | `PortfolioDetailView` | Детали с позициями и историей |
| `/portfolios/<pk>/delete/` | `PortfolioDeleteView` | Удаление портфеля |
| `/portfolios/<pk>/buy/` | `PortfolioBuyView` | Покупка акции |
| `/portfolios/<pk>/sell/` | `PortfolioSellView` | Продажа акции |

### 3.4 Сервисный слой

- `PortfolioService` — создание портфеля, покупка, продажа, расчет сводки

### 3.5 Ограничения

- Портфель виртуальный — реальные сделки не совершаются
- Баланс портфеля уменьшается при покупке и увеличивается при продаже
- Текущая стоимость позиции зависит от `Share.last_price`, который обновляется через Celery или демонстрационные данные

## 4. Исторические цены и графики

### 4.1 Модель данных

| Модель | Описание | Ключевые поля |
|--------|----------|---------------|
| `PriceHistory` | Историческая цена | `share`, `price`, `timestamp` |

### 4.2 Функциональность

- **Хранение исторических цен** — сохранение свечей в БД через задачу `update_price_history`
- **Получение истории** — выборка по акции и периоду
- **Отображение на графиках** — существующий график Plotly на странице детальной информации об акции теперь поддерживает демонстрационные данные
- **Разные временные периоды** — параметр `days` при загрузке истории (по умолчанию 180 дней)

### 4.3 Сервисный слой

- `PriceHistoryService` — сохранение свечей, загрузка из Tinkoff API или демо, получение истории

### 4.4 Ограничения

- График на странице детальной информации по умолчанию загружает 180 дней
- Для пользовательского выбора периода требуется доработка интерфейса

## 5. Симулятор инвестиционных стратегий

### 5.1 Функциональность

- **Создание стратегии** — на основе правил покупки и продажа (функции условий)
- **Запуск на исторических данных** — симуляция по сохраненным в БД свечам
- **Отображение сделок** — список всех виртуальных покупок и продаж
- **Показатели эффективности** — общая доходность, доходность в %, максимальная просадка, число сделок

### 5.2 Сервисный слой

- `StrategySimulatorService.simulate()` — запуск симуляции с настраиваемыми условиями покупки/продажи

### 5.3 Пример использования

```python
from dashboard.services.price_history_service import StrategySimulatorService
from decimal import Decimal

result = StrategySimulatorService.simulate(
    share,
    start_date=start,
    end_date=end,
    initial_balance=Decimal("10000"),
    buy_condition=lambda price, ctx: price < Decimal("150") and ctx["balance"] >= price,
    sell_condition=lambda price, ctx: price > Decimal("200") and ctx["shares_held"] > 0,
)
# result содержит: final_value, total_return, trades, max_drawdown, portfolio_values
```

### 5.4 Ограничения

- Симулятор использует только данные из `PriceHistory` (то, что было сохранено в БД)
- Нет интеграции с веб-интерфейсом для настройки стратегий (требует доработки UI)

## 6. Демонстрационный механизм рыночных данных

### 6.1 Почему нужен

Tinkoff Invest API требует действительного `TINKOFF_TOKEN`, который может быть недоступен. Для обеспечения работоспособности функций без внешнего API реализован демонстрационный механизм.

### 6.2 Реализация

Файл: `dashboard/services/demo_market_data.py`

- `get_last_data_demo(share)` — возвращает синтетическую цену (базовая цена ±5%) и текущее время
- `get_candles_demo(share, days, interval)` — генерирует синтетические исторические свечи

Базовые цены для известных тикеров (AAPL, GOOGL, MSFT, AMZN, TSLA, NVDA, META, NFLX). Для неизвестных тикеров используется цена $100.

### 6.3 Интеграция

- `market_data.get_last_data()` — при ошибке Tinkoff API переходит на демо-данные (если `use_demo_fallback=True`)
- `graph.get_graph()` — при ошибке API строит демо-график с оранжевой линией

### 6.4 Ограничения demonstration данных

| Аспект | Описание |
|--------|----------|
| Данные нереальные | Цены генерируются случайно, не отражают реальный рынок |
| Базовые цены | Фиксированные значения для известных тикеров, $100 для остальных |
| Нет реальных связей | Изменения цен не зависят от реальных рыночных событий |
| Только для разработки/демо | Не использовать для принятия реальных инвестиционных решений |

### 6.5 Как использовать реальный API

1. Получить `TINKOFF_TOKEN` от Tinkoff Invest
2. Установить переменную окружения: `export TINKOFF_TOKEN=<ваш_токен>`
3. Демо-режим автоматически отключится при успешном ответе от API

## 9. Известные ограничения и план доработок

| # | Ограничение | План |
|---|-------------|------|
| 1 | Симулятор стратегий не имеет веб-интерфейса для настройки | Добавить формы и представления для создания и запуска стратегий |

| 3 | Ценовые уведомления проверяются только при обновлении цен (каждые 10 сек по умолчанию) | Это приемлемо для текущей архитектуры |

| 5 | Токен Tinkoff API может быть недоступен | Демо-режим обеспечивает работоспособность без токена |
| 6 | `update_price_history` в celery beat с жестким share_id=1 | Требует настройки под конкретную акцию или динамическое определение |

## 10. Запуск и проверка

Для запуска приложения с новыми функциями:

1. Установить зависимости: `pip install -r requirements.txt`
2. Запустить PostgreSQL и Redis: `docker-compose up -d`
3. Применить миграции: `python manage.py migrate`
4. Запустить сервер: `python manage.py runserver`
5. Для фоновых задач: `celery -A config beat` и `celery -A config worker -l info`
6. Запустить тесты: `python manage.py test dashboard.tests`

Тесты покрывают:
- Демонстрационные рыночные данные
- Списки наблюдения (создание, добавление, удаление, защита от дублей)
- Ценовые уведомления (создание, срабатывание, защита от дублей, создание уведомлений)
- Виртуальный портфель (покупка, продажа, проверка баланса, сводка)
- Исторические цены (сохранение, выборка)
- Симулятор стратегий (запуск, показатели эффективности)
